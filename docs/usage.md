# 接入、证书与保存

## 选择接入通道

| 接入方式 | 客户端设置 | Ferret 设置 |
| --- | --- | --- |
| 本机 HTTP(S) 代理 | 手工设置 `127.0.0.1:8080`，或由系统代理开关设置 | 勾选系统代理可自动配置 Windows；开始后采集 |
| 局域网 HTTP(S) 代理 | 代理指向电脑的局域网地址和 regular 端口 | 监听地址改为 `0.0.0.0`，允许对应防火墙入站连接 |
| local 进程抓包 | 客户端无需配置代理 | 选择 local，可按进程名或 PID 过滤；按系统提示授予驱动所需权限 |
| WireGuard | 每台设备扫描自己的二维码 | 开启 WireGuard，在设备管理中添加设备，确保各设备的 UDP 端口可达 |
| 反向代理 | 直接访问 Ferret 的 reverse 监听地址 | 配置 HTTP(S) 目标与独立监听端口 |
| SOCKS5 | 设置 Ferret 地址与 SOCKS5 端口（默认 1080） | 开启 SOCKS5；仅支持 TCP CONNECT |

regular 默认只监听环回地址，局域网设备不能直接访问该端口；WireGuard 开启接通后独立监听可供局域网设备访问的 UDP 端口。监听地址用于绑定，页面中的局域网地址用于客户端接入，Windows 系统代理始终写 `127.0.0.1`。上游代理只改变 regular 出口，其余通道仍直接访问目标。

「停止」结束抓包会话并恢复系统代理；内核可继续监听供 Compose 使用。尚未完成的断点应按界面操作放行或丢弃。使用系统代理的应用才受 Windows 代理设置影响；UWP 应用的环回权限需按具体应用配置，Ferret 不自动修改全机 UWP 豁免。

## WireGuard 多设备

在抓包设置中打开 WireGuard 设备管理，为每台手机或电脑添加独立设备，再扫描该设备的二维码。每台设备使用独立密钥和 UDP 端口；同一二维码只能供一台设备使用。旧版本的二维码保留为“默认设备”，其他手机需添加新设备并重新扫码。

设备配置会独立保存；查看二维码不会开始监听，点击“开始抓包”才接通已启用设备。列表中的“监听就绪”表示服务端端口已启动，不代表手机在线。端口被占用或防火墙未放行时，应检查对应设备的端口。更换密钥后需重新扫码，停用或删除设备会撤下它的监听。

流量表的“设备”列和详情显示来源，可用 `~meta "设备名称"` 筛选；原生 `.flow` 会话保留来源，HAR 不保证保留自定义信息。多设备共享当前抓包工作区的重写、脚本和 Mock；全局固定会话会共享 Cookie/认证缓存，因此多台 WireGuard 设备接通前必须关闭该功能。

## HTTPS 证书

本机客户端需要信任「证书」页显示的 Ferret CA。局域网设备设置 HTTP 代理后访问 `http://ferret-ca/` 下载 PEM，并在设备系统设置中安装、启用该 CA 的信任。证书锁定或自带信任库的应用可能需要单独配置。

「额外信任的上游 CA」用于企业或自签名源站，不代替客户端信任 Ferret。「客户端证书」用于上游 mTLS，可以选择 PEM 文件或按 `<主机名>.pem` 命名的目录。重新生成 Ferret CA 后，客户端也需要更新信任的证书。

## 保存与更新

抓包列表、磁盘会话、手动导出是不同入口。自动会话录制随「开始抓包」启动，所有接入通道统一落盘，与是否勾选系统代理无关；磁盘录制目前只保存 HTTP 流量，其他协议请在列表中手动导出。会话可导入 `.flow`，流量可导出 HAR、raw 或请求命令。SSE 的长期观察和正文缓冲受容量上限约束，截断标记会保存在流量中。

安装版在「设置」中检查、下载更新，确认重启后先恢复代理并停止内核，再应用更新。源码和便携版通过 [Releases](https://github.com/JunctureHao/ferret/releases) 下载。每版变更见对应 release 的提交清单。

安装数据保存在 Windows Roaming 下的 Ferret 数据目录；安装根由 Velopack 管理。升级前需要手动备份时，备份数据目录中的配置、证书、会话和脚本。
